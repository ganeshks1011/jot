# Jot — Extension Implementation Plan

A production-ready Google Chrome extension (Manifest V3): a contextual AI writing assistant that rewrites and formats selected text inside any page, with a Raycast/Spotlight-style keyboard-first interface.

> **Note:** the extension is named **Jot**; the sibling backend service remains **wurkflo** (the `wurkflo` provider adapter refers to that backend).

**Stack:** WXT · Vite · React 19 · TypeScript · Tailwind CSS v4 · HeroUI v3 (`@heroui/react` + `@heroui/styles`) · lucide-react
**Status:** In development.

> **Scope:** targets short-form editable fields — textarea, `input[type=text]`, and contenteditable elements such as email bodies (Gmail), chat/DM boxes (Slack, LinkedIn), comments, and web forms. Does NOT target canvas-rendered document editors (Google Docs, Figma text layers, etc.) — those have no DOM text nodes to insert into and are out of scope for this iteration.

---

## 1. Decisions (locked during planning)

| Decision | Choice | Rationale |
|---|---|---|
| Framework | **WXT** | Purpose-built for MV3: auto-generated manifest, typed entrypoints, first-class HMR, simple content-script module system. |
| Component library | **HeroUI v3** (Tailwind v4 + React Aria) | CSS-variable oklch theming; styles inlined at build — zero runtime/CDN dependencies; no required provider, no framer-motion (CSS-based animations). |
| Provider abstraction | **OpenAI + wurkflo** — both OpenAI-compatible | Single `ProviderAdapter` interface; wurkflo is a drop-in later. Both POST `{baseUrl}/chat/completions` with `Authorization: Bearer`. |
| Model dropdown | **Dynamic fetch from `GET {baseUrl}/models`** | Live model list when base URL + key are set; free-text manual entry as fallback. |
| UI container | **`chrome-extension://` iframe (overlay) injected by the content script** | No browser-action popup; the entire UI renders inside an iframe near the active field, cross-origin-safe via `postMessage`. |
| Settings surface | **Overlay iframe view + dedicated options page** | The overlay iframe keeps the rewrite flow with a settings toggle; options page hosts full configuration. |
| Theming | **Follow system theme** via HeroUI `data-theme` (light-first, `dark:` variants) | A small helper applies `matchMedia('(prefers-color-scheme: dark)')` to the document root — no manual toggle, tracks the OS. Not dark-first. |
| Tier enforcement | Client-side mock counters (free 20 / pro 1,000 per month) | No real backend yet. wurkflo provider will enforce server-side later; client counter remains as fallback. |
| API key storage | `chrome.storage.local` only (never `sync`) | `sync` uploads to Google's servers; keys stay local, masked in UI, never logged. |
| Insertion targets | textarea / input / contenteditable only | Canvas-based editors (Docs, Figma) have no DOM text to target; explicitly out of scope. |

## 2. Manifest (generated by `wxt.config.ts`)

- **Permissions:** `storage`, `activeTab`, `scripting` — no more, no less.
- **Host permissions:** **none.** Jot has no standing access to any website.
- **Content scripts:** **none** registered in the manifest. Page code (`jot-host.ts`, an unlisted script) is injected via `chrome.scripting.executeScript` only after the user explicitly invokes Jot (keyboard shortcut / action click); activeTab grants temporary access to just that tab, and closing the overlay tears the controller down completely.
- **Web-accessible resources:** `overlay.html` for `http(s)://*/*` so pages can embed the iframe when invoked (WAR grants no access to those pages; no `use_dynamic_url` — it corrupted `chrome.runtime.getURL()` output in testing). `auth-callback.html` scoped to the Wurkflo origin.
- **Commands:** `toggle-jot` → Ctrl/Cmd+Shift+Space
- **Icons:** 16/32/48/128 (generated sparkles glyph on indigo→violet gradient)

## 3. Backend abstraction

### `src/lib/providers.ts`

```ts
type ProviderId = "openai" | "wurkflo";

interface ProviderAdapter {
  id: ProviderId;
  label: string;
  tiersEnforcedServerSide: boolean;      // false for openai (client counters), true for wurkflo
  listModels(baseUrl: string, apiKey: string): Promise<string[]>;
  rewrite(system: string, user: string, opts: LLMOpts): Promise<string>;
}
```

- `openaiAdapter` — default `https://api.openai.com/v1`, user supplies base URL + API key + model. Works with any OpenAI-compatible endpoint (DeepSeek, LM Studio).
- `wurkfloAdapter` — same OpenAI-compatible fetch shape, configured base URL + optional key/model; tier limits enforced server-side. Built now as a working stub behind the interface so it is drop-in replaceable.
- `ollamaAdapter` — first-class builtin (`http://localhost:11434/v1`, recommended model `qwen2.5`). Implemented: keyless loopback requests send no `Authorization` header (local, no auth).

### `src/lib/api.ts` — request flow

Runs in the **overlay iframe** (and the options page) under the extension's own CSP, where it can fetch providers directly — the overlay is a `chrome-extension://` document and is not bound by the host page's CSP (see §6). The content script never calls it directly; the background service worker may still be used for background-only operations (e.g., usage counters). The flow:

1. `resolveActiveProvider()` → read active provider + config from settings.
2. **Tier guard** (client-side, for providers without server enforcement): check monthly counter, decrement on success, throw `TierExhaustedError` when spent.
3. Build system + user prompts from style + follow-up.
4. `adapter.rewrite()` → parse `choices[0].message.content`.
5. Persist usage; surface errors as typed results (auth / rate-limit / network / tier-exhausted).

### Settings schema

```ts
interface Settings {
  backend: {
    provider: ProviderId;                    // "openai" | "wurkflo"
    openai: { baseUrl: string; apiKey: string; model: string };   // apiKey in storage.local
    wurkflo: { baseUrl: string; apiKey?: string; model?: string };
  };
  tier: "free" | "pro";
  siteDefaults: Record<string, StyleId>;     // hostname → default style
}
```

- Non-secret settings → `chrome.storage.sync`; secrets (`apiKey`) → `chrome.storage.local`.
- Cap `siteDefaults` to the most recent N hostnames (e.g. 50) before writing to `chrome.storage.sync` — sync has a 100KB total / 8KB per-item quota and this field has no natural upper bound otherwise.

## 5. Overlay UI & keyboard contract

### Flow state machine
`idle → generating → output → tweaking` — on open, the overlay receives the active field + selection captured by the content script via `postMessage` (see §6). Falls back gracefully when opened with no focused editable (e.g., the shortcut pressed on a page with no text field).

### Views (within the iframe)
- **Rewrite** (only view): source line → borderless result preview → feedback input. Single implicit mode resolved per open (per-site > global > casual); no style switching in the overlay.

### Components (HeroUI v3)
- **Content panel:** borderless read-only `TextArea`, scrollable, with `Skeleton` loading state while a rewrite is in flight.
- **Feedback input:** `Input`, state-dependent placeholder ("What would you like to say?" idle, "Make it shorter, warmer, more direct..." after output), Enter submits the tweak.
- **Chrome:** `Button` (primary/pending for generate), `Skeleton`, `Spinner`.

### Global `keydown` contract
| Key | Behavior |
|---|---|
| `Arrow Up/Down` | Cycle content → feedback sections. |
| `Enter` | Context-aware: feedback input focused → submit tweak; content box focused → post `{ type: 'insert', text }`, show brief "Inserted", then post `{ type: 'close' }`. |
| `Escape` | Clear state → close follow-up box → post `{ type: 'close' }`. |
| `Tab` / `Shift+Tab` | Settings → close → content → feedback input (focus trap, wraps). |
| Focus rings | HeroUI/React Aria `data-focus-visible` rings kept on every interactive element — never overridden by custom focus-visible styles. |

### postMessage contract (overlay → parent)
- `{ type: 'resize', height }` on mount and whenever panel content height changes (ResizeObserver).
- `{ type: 'insert', text }` on commit (Enter on content box).
- `{ type: 'insertLexical', map, text }` on commit when the host supplied Lexical nodes (keyed rewrite; `text` is the plain fallback).
- `{ type: 'close' }` on Escape, after insert confirmation, or on settings→back.

## 6. Injected host controller (on-demand)

There is no persistent content script. The only page-facing code is `src/entrypoints/jot-host.ts`, an unlisted script injected with `chrome.scripting.executeScript({ files: ["/jot-host.js"] })` when the user invokes Jot (chrome.commands shortcut or action click → background → `tabs.sendMessage("TOGGLE_OVERLAY")` fast-path toggle, falling back to injection). On invocation it:

- captures the writing context from `document.activeElement` (textarea / text-like input / contenteditable) or the active DOM selection — nothing else is read;
- creates the `chrome-extension://` overlay iframe anchored to the field (top-center fallback when there is no anchor);
- installs its postMessage listener, and **tears everything down on close** — iframe removed, listeners detached, controller state deleted.

**Invocation flow:**

```
Cmd/Ctrl+Shift+Space  OR  toolbar icon click
        ↓ background worker
get active tab → tabs.sendMessage("TOGGLE_OVERLAY")   ← closes if already open
        ↓ (no receiver)
chrome.scripting.executeScript(files: ["jot-host.js"]) ← activeTab grant required
        ↓
capture field/selection → open overlay iframe
```

Because there is no persistent presence, arbitrary in-page shortcuts and the sparkle button cannot exist; the chrome.commands shortcut is the trigger. Pages where Chrome blocks scripting (`chrome://`, Web Store) surface a small extension-origin notice window ("Jot can't work on this page.") instead of raw permission errors.

**Communication contract:** identical to the former content-script bridge — the controller captures field + selection and posts `{ type: 'init', ... }` into the iframe via `postMessage` (re-sent when the overlay replies `{ type: 'ready' }`, closing the mount race). The iframe posts back `{ type: 'resize', height }`, `{ type: 'insert', text }`, `{ type: 'close' }`. The controller validates `event.origin` against the extension's own origin (derived from `chrome.runtime.id`) before acting — a strict `event.source === iframe.contentWindow` comparison is unreliable across the isolated world's WindowProxy wrappers — and performs the Range/DOM insertion itself.

Provider fetch calls never touch the host page: the overlay iframe relays every request through the background service worker (`src/lib/net.ts`), which is not CORS-bound (Jot has no host permissions). See §3.

## 7. Options page & settings

All settings (including the API key) live in the **dedicated options page** (`src/entrypoints/options/`, opens in its own tab via `options_ui.open_in_tab`). The overlay UI contains no settings.

- **Provider:** DeepSeek (default) / OpenCode Go / OpenAI / Claude / Gemini / wurkflo dropdown.
- **Backend (BYOG):** base URL (defaults per provider), masked API key (shown as `••••`, edit to replace; **"Get a {provider} API key"** link opens the provider's key page), model + **Load models** (populated from `GET {baseUrl}/models`, shown as selectable chips), with free-text model fallback on auth/parse failure. Anthropic/Gemini use their OpenAI-compatible endpoints and may not support `GET /models`. Wurkflo shows a sign-in card instead of endpoint fields.
- **Wurkflo:** base URL + optional key/model (stub fields for the follow-up backend).
- **Tier management:** free (20 texts/month) vs pro (1,000 texts/month) selector, live usage meters. Client-side counters are a soft usage limiter, not enforcement — a user with devtools access can reset them. Real enforcement is deferred to the wurkflo backend (see section 10, Out of scope).
- **Per-website defaults:** table mapping hostname → default style (e.g., `linkedin.com` → Professional, `slack.com` → Casual). The overlay auto-selects the style for the active tab's hostname.
- **Key storage:** `chrome.storage.local` (never `sync`); non-secret config in `chrome.storage.sync`.
- **Overlay behavior:** when the overlay opens it **automatically rewrites** the captured selection using the configured provider; if no key is set it shows a "Open settings" action that opens the options page (`chrome.runtime.openOptionsPage()`).

## 8. Design system (HeroUI v3 · theme-aware)

- **Component library:** HeroUI v3 (`@heroui/react` + `@heroui/styles`, Tailwind v4 + React Aria under the hood). All CSS is compiled and **inlined into the extension's built stylesheets at build time** — no external/CDN runtime dependencies, no webfonts (system font stack).
- **Theming:** HeroUI v3 oklch CSS variables, switched via `data-theme` / `.dark` on the document root. A small theme helper applies the system preference (`matchMedia('(prefers-color-scheme: dark)')`, live-updating via a `change` listener) to the overlay/options documents. Light-first, with dark variants following the OS.
- **Brand accent:** `--accent` / `--accent-soft` overridden in `@layer base` for both themes to the indigo→violet identity; gradient moments (selected chip indicator, tier badge, sparkles) use Tailwind gradient utilities on top of HeroUI tokens. Brand extension: red-500 → violet-600 glow system (`--brand-glow-from/to`, `--brand-gradient`) for the composer highlight, overlay card glow, connector, and borderless textbox halo — soft diffusion only (alpha ≤28%, blur ≥8px), never neon. Motion: 6s gradient sweep on gradient surfaces, 4s glow breathe on the card; composer glow static; `prefers-reduced-motion` disables all of it.
- **Overlay panel:** self-contained floating card — `rounded-2xl` (16px), translucent `bg-surface/75 backdrop-blur-xl`, soft border + layered `surface-shadow`; follows the system theme independent of the host page.
- **Focus:** HeroUI/React Aria `data-focus-visible` rings on every interactive element (no custom focus-visible overrides).
- **Micro-interactions:** `transition-all duration-250`, `active:scale-[0.99]`; HeroUI v3 animations are CSS-based (no framer-motion dependency).

## 9. Verification & QA checklist

1. `npm install`
2. `npm run build` → `.output/chrome-mv3` → load unpacked in `chrome://extensions`.
3. `npm run typecheck` (strict `tsc --noEmit`).
4. Manual QA:
   - [ ] Invocation via Ctrl/Cmd+Shift+Space and toolbar click opens the overlay near Gmail / Slack / LinkedIn / Twitter compose fields; insertion replaces selection in textarea, input, and contenteditable fields.
   - [ ] No Jot code runs before invocation: load a page, do nothing, confirm no overlay/sparkle/controller exists; invoke, use, close, navigate — nothing remains injected.
   - [ ] Restricted pages (`chrome://extensions`, Chrome Web Store) show the "Jot can't work on this page." notice window; no raw permission errors.
   - [ ] Keyboard-only overlay flow (arrows, Enter, Escape, Tab) with no mouse; Enter commits via `postMessage`; Escape closes and tears down.
   - [ ] `postMessage` contract: content script validates `event.source`/`event.origin`; resize/close/insert events handled correctly.
   - [ ] Style chips: Left/Right arrows wrap around; Enter regenerates in the selected style; selected chip shows gradient accent.
   - [ ] Follow-up tweak box auto-focuses after generation; tweaks chain into the prompt; Skeleton shows while in flight.
   - [ ] OpenAI provider: model dropdown loads from `/models`; manual fallback works; masked key.
   - [ ] Ollama path (`http://localhost:11434/v1`) rewrites with no auth header and no `OLLAMA_ORIGINS` setup (requests relay through the background worker, so CORS no longer applies).
   - [ ] wurkflo provider stub resolves and routes (drop-in shape verified).
   - [ ] Tier counters: free 20 / pro 1,000 decrement; friendly upgrade toast on exhaustion.
   - [ ] Per-site default auto-selected from hostname; override persists.
   - [ ] Light and dark themes both render correctly (system toggle).

## 10. Out of scope (this iteration)

- Server-side tier enforcement (requires the wurkflo backend to exist — adapter stub only).
- Accounts/auth in the extension; real quotas derive from the wurkflo backend later.
- Streaming responses (parsed JSON completions only).
- Canvas-rendered document editors (Google Docs, Figma) — no DOM text nodes to insert into (see Scope note above).
